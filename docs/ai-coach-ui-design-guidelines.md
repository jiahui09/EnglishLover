# EnglishLover AI Coach UI 设计优化与细化方案

> 文档定位：目标产品方案 / UI 设计执行稿
> 设计要求：信息高效、画面直观简洁、提高专注力。
> 适用范围：今日学习、单词训练、阅读训练、教练建议；学习画像首版并入教练建议页摘要。
> 关联文档：`DESIGN.md`、`docs/ai-coach-prd.md`、`docs/ai-coach-information-architecture.md`、`docs/ai-coach-core-page-copy-and-interactions.md`。
> 范围边界：描述 UI 层级、视觉语言、组件规则、状态和验收；不描述后端接口、数据库或部署。

---

## 1. 设计目标

EnglishLover AI Coach 的首版界面不是数据看板，也不是课程商城，而是一个每天把用户带入学习闭环的私人教练。界面要让用户少判断、少选择、少被打断。

### 1.1 三条设计准则

| 准则 | 执行要求 | 避免 |
|---|---|---|
| 信息高效 | 每个模块只展示能支持下一步行动的信息 | 大段解释、重复统计、泛泛鼓励 |
| 画面直观简洁 | 用清晰层级、留白、卡片和状态标签表达结构 | 重型图表、炫彩渐变、装饰性插画 |
| 提高专注力 | 学习流程中每屏只保留一个主行动 | 多个同级按钮、弹窗打断、无关入口 |

### 1.2 首版成功体验

用户打开首页后应在 10 秒内知道：

```text
今天先做什么 -> 为什么做 -> 点哪里开始
```

用户完成一个页面后应立刻知道：

```text
刚完成了什么 -> 暴露了什么问题 -> 下一步做什么
```

## 2. 设计哲学与取舍

本方案不是把多种设计风格混合堆叠，而是为 EnglishLover AI Coach 选择一条清晰路线：**以格式塔组织信息，以极简主义降低认知负荷，以轻量 Material 建立可预测层级，以包容性设计兜住真实学习场景，以原子设计保证后续实现一致。**

### 2.1 哲学采用矩阵

| 设计哲学 | 本项目采用方式 | 明确限制 |
|---|---|---|
| 格式塔 | 作为视觉组织底层语法，决定卡片分组、按钮归属、阅读路径和反馈区层级 | 不用装饰性分组；分组必须服务任务理解 |
| 极简主义 | 作为主体验策略，减少入口、统计和干扰，让单词与阅读成为主角 | 极简不是信息不足；必要反馈和可访问性不能被删掉 |
| 扁平化设计 | 保留清晰色块、纯排版和跨平台一致性 | 不采用高饱和扁平营销风，也不牺牲层级提示 |
| Material Design | 作为 Flutter 落地基础，使用表面、边界、轻量 elevation 和合理动效 | 不做复杂纸张隐喻；阴影只用于区分可操作层级 |
| 新拟物化 | 仅吸收“轻微触觉”的提醒：按钮和卡片可有温和形体感 | 不大面积使用内外阴影，不使用低对比软 UI 承载功能 |
| 包容性设计 | 强光、单手、低视力、低注意力、网络慢等情境默认纳入规则 | 不把无障碍当后补选项；颜色不能单独表达语义 |
| 以用户为中心 | 所有页面围绕用户问题：今天怎么学、当前怎么做、下一步是什么 | 不为技术便利或视觉偏好牺牲学习路径 |
| 情感化设计 | 本能层安静精致，行为层顺滑明确，反思层让用户记住“词进入阅读”闭环 | 不用夸张庆祝、排行榜或焦虑刺激制造情绪 |
| 原子设计 | 用 token -> atom -> molecule -> organism -> template -> page 组织实现 | 不为了系统化制造无用抽象；首版组件以可复用但轻量为准 |

### 2.2 最终风格判断

EnglishLover AI Coach 的最终风格是：**极简考研学习界面**。

- 主视觉不是绿色健康管理工具，也不是大面积深色工具界面，而是 **Study Paper + Warm Card + Oxford Blue + Word Ochre**，服务考研学子的稳定、可信和长期专注。
- 不是纯扁平：因为学习流程需要可预测的层级、可点击意符和状态过渡。
- 不是新拟物：因为低对比软 UI 会削弱阅读、答题和弱项提醒的可访问性。
- 不是数据看板：因为用户首要任务不是分析数据，而是完成今日学习。
- 不是营销页：因为视觉记忆点来自“单词 -> 阅读 -> 解析 -> 建议”的学习闭环，而不是炫技装饰。

### 2.3 格式塔布局语法

| 原则 | UI 规则 | 典型位置 |
|---|---|---|
| 邻近性 | 同一任务的标题、说明、关键数据和按钮必须在同一卡片内；跨任务内容保持足够间距 | 首页任务卡、教练建议卡 |
| 相似性 | 同类状态使用同一形状、字号和色彩权重；主行动只用 Oxford Blue，薄弱词提醒只用 Word Ochre，错误风险只用 Brick Red | 任务状态、词汇标签、题型标签 |
| 连续性 | 学习路径必须沿“今日 -> 单词 -> 阅读 -> 解析 -> 建议”连续呈现 | 首页闭环轨迹、结果页下一步 |
| 封闭性 | 卡片边界定义任务范围，不靠分割线堆叠制造复杂结构 | 单词卡、阅读正文、解析区 |
| 共同命运 | 同一阶段的元素一起出现、一起淡出；阅读正文、题目、解析分阶段切换 | 专注模式、生成中、答题中 |

### 2.4 用户中心决策顺序

当 UI 方案发生冲突时，按以下顺序裁决：

```text
学习任务清晰度 > 阅读和背词专注度 > 可访问性 > 实现一致性 > 视觉新鲜感
```

任何新增入口、动效、装饰或统计面板都必须回答：它是否帮助用户更快完成当前学习闭环。如果答案是否定的，应删除或折叠。

## 3. 视觉方向

### 3.1 设计关键词

- 安静学习桌；
- 私人教练便签；
- 单词进入阅读语境的闭环轨迹；
- 低干扰、低焦虑、明确下一步。

### 3.2 色彩 token

最终方案采用“沉稳靛蓝 + 暖纸张浅色 + 石板深色 + 暖橙词汇语义”的组合：全局主色稳定可信，阅读背景低刺激，词汇重点有温度，夜间备考不刺眼。

#### 3.2.1 浅色模式

| Token | Hex | 用途 |
|---|---:|---|
| Background / Study Paper | `#F6F1E8` | 全局暖纸张背景，降低纯白刺眼感 |
| Surface / Warm Card | `#FFFCF6` | 卡片、阅读正文、输入区域 |
| Surface Elevated | `#FFFCF6` | 浅色模式保持卡片温润统一，靠边界/阴影分层 |
| Primary / Oxford Blue | `#334E7E` | 主按钮、当前进度、选中导航、品牌标识 |
| Primary Dark | `#263B60` | 主按钮 hover / pressed、高强调状态 |
| Primary Soft | `#E8EEF8` | 当前任务提示、选中导航浅底、教练建议浅表面 |
| Success | `#20C997` | 正确、已掌握、完成反馈 |
| Success Soft | `#DDF9F1` | 成功浅底，不抢主行动 |
| Word / Warning | `#94551F` | 薄弱词、待复习、目标词、注意提示 |
| Word Soft | `#F7E8D2` | 薄弱词标签、目标词轻标记、提醒浅底 |
| Error | `#A34A3F` | 错误和生成失败，不用于惩罚性文案 |
| Error Soft | `#F7E6E2` | 错误、降级和风险提示浅底 |
| Text | `#24252B` | 标题、正文、关键文本 |
| Muted Text | `#6B6870` | 辅助说明、时间、次级标签 |
| Border / Desk Line | `#E5D8C6` | 分割线、边框、禁用边界 |
| Quiet Surface | `#EFE6D8` | 低优先级分隔、进度底色、弱背景差 |

#### 3.2.2 深色模式

| Token | Hex | 用途 |
|---|---:|---|
| Background | `#0F172A` | 夜间备考背景；不用纯黑，避免强刺激 |
| Surface | `#111827` | 普通卡片、阅读容器、底部导航 |
| Elevated Surface | `#1E293B` | 二级信息块、题目卡、弱背景差 |
| Primary | `#8BA4F9` | 深色模式主按钮、进度、选中导航 |
| Primary Dark | `#6F8EEA` | 深色模式 hover / pressed |
| Primary Soft | `#1E2A44` | 选中浅底、提示块、教练建议浅表面 |
| Success | `#34D399` | 正确、已掌握、完成反馈 |
| Success Soft | `#123326` | 深色成功浅底 |
| Word / Warning | `#E0A34B` | 薄弱词、待复习、目标词、注意提示 |
| Word Soft | `#2A2116` | 深色词汇提醒浅底 |
| Error | `#F87171` | 错误、AI 降级、不可恢复风险 |
| Error Soft | `#3A1F23` | 深色错误浅底 |
| Text | `#E2E8F0` | 标题、正文、关键文本 |
| Muted Text | `#94A3B8` | 辅助说明、时间、次级标签 |
| Border | `#334155` | 分割线、边框、禁用边界 |
| Quiet Surface | `#1E293B` | 进度底色、弱背景差 |

使用限制：

- 每个页面的主行动色只能是 Oxford Blue / 深色 Primary，不再使用绿色作为品牌主色，也不使用大面积深蓝实心块制造压迫感。
- Soft token 只可作为浅表面或状态底色，不能替代主按钮色。
- Word / Warning 只用于学习风险、目标词或薄弱词，不用于装饰。
- Success 只表达“正确 / 已掌握 / 完成”，不能用于品牌或主要导航。
- Error 仅用于错误、AI 降级和不可恢复风险，不用于评价用户表现。
- 不使用彩虹渐变、霓虹色、荧光色或营销页式大面积高饱和背景。
- 深色模式必须跟随系统主题，并保证正文、按钮、提醒色在深色背景下可读。

考研场景色彩判断：

- Oxford Blue 给人稳定、理性、可信和长期陪伴感，适合作为私人教练和学习主行动色。
- Study Paper 与 Warm Card 弱化屏幕压迫感，更接近阅读桌面，不和英文正文竞争注意力。
- Slate 深色模式服务夜间学习和熬夜备考，不使用纯黑或高饱和亮色。
- Word / Warning 只负责词汇重点与薄弱项，让“需要复习”被看见，但不制造红色警报感。
- Error 只表达系统错误或不可恢复风险，不评价学生能力，避免焦虑刺激。
- 推荐色彩比例：70% 中性背景/表面、20% 文本与边界、8% 主色、2% 词汇/成功/错误语义色。

### 3.3 表面层级与 Material 取舍

| 层级 | 表面 | 视觉规则 | 用途 |
|---|---|---|---|
| Level 0 | Study Paper 背景 | 无阴影，低饱和底色 | 页面底层、普通导航背景 |
| Level 1 | Warm Card 表面 | 细边框或极轻阴影，圆角 18–24px | 任务卡、教练建议、结果摘要 |
| Level 2 | Focus 表面 | 更高对比白底，弱化外部导航 | 单词专注模式、阅读正文、答题区 |
| Level 3 | Feedback 表面 | 语义色浅底 + 文案 + 图标 | 错误、降级、成功、提醒 |

Material 只用于建立“什么可点击、什么属于同一层、什么是当前任务”的心理模型。禁止为了质感而叠加厚重阴影、玻璃拟态或新拟物内阴影。

### 3.4 字体与排版

当前 Flutter 项目已通过 shadcn_ui 使用 Geist / system sans fallback 建立排版基础；首版不新增项目自定义字体资产，而是通过字号、字重和间距建立秩序。

| 层级 | 建议尺寸 | 用法 |
|---|---:|---|
| 页面标题 | 24–28sp / 600–700 | 首页、训练页、教练建议页标题 |
| 卡片标题 | 18–20sp / 600 | 任务卡、结果卡、建议卡标题 |
| 正文 | 16sp / 400 | 普通说明、题目、解析 |
| 阅读正文 | 17–18sp / 400，行高 1.55–1.7 | 阅读文章，优先可读性 |
| 标签/数据 | 12–14sp / 500 | 进度、状态、题型标签 |

文案排版规则：

- 标题不超过 16 个汉字；
- 卡片说明控制在 1–2 行；
- 教练建议使用“判断 / 原因 / 下一步”三段，不写成长报告；
- 阅读正文段落之间保留明显间距。

### 3.5 空间与形状

| 项 | 规则 |
|---|---|
| 页面左右边距 | 移动端 20px；桌面端内容列最大宽度 720–840px |
| 卡片内边距 | 16–20px |
| 卡片间距 | 12–16px |
| 圆角 | 卡片 18–24px；按钮 14–16px |
| 阴影 | 只允许 Level 1 / Level 2 两档轻量 elevation；优先边框和背景差 |
| 分割线 | 只在信息层级需要时使用 |
| 新拟物限制 | 不使用大面积内阴影、低对比凸起或凹陷承载核心操作 |

### 3.6 签名元素：学习闭环轨迹

为避免通用模板感，EnglishLover 的标志性 UI 元素是“学习闭环轨迹”：

```text
单词 -> 阅读 -> 解析 -> 建议
```

呈现规则：

- 首页可用横向或纵向四步短路径显示今日闭环进度；
- 结果页用当前完成节点高亮下一节点；
- 不做复杂动画，最多用轻微状态过渡；
- 轨迹是结构提示，不是装饰图案。

## 4. 页面级设计

### 4.1 今日学习：首页

#### 页面目标

回答“我今天该怎么学？”，并把用户带入最短学习路径。

#### 信息优先级

1. 今日一句话计划；
2. 当前最推荐任务；
3. 单词/阅读两个任务状态；
4. 简短教练提示；
5. 今日完成进度。

#### 推荐结构

```text
今日学习
├── 顶部：问候 + 今日一句话计划
├── 闭环轨迹：单词 -> 阅读 -> 解析 -> 建议
├── 主任务卡：当前最该做的一步
├── 次级任务卡：单词 / 阅读状态摘要
├── 教练便签：一句判断 + 一个入口
└── 底部导航：今日 / 单词 / 阅读 / 教练
```

#### 首屏示例

```text
今天先把近期词放进阅读里
15–25 分钟 · 单词 20 个 · 阅读 1 篇

[闭环轨迹：单词 进行中 -> 阅读 -> 解析 -> 建议]

当前建议
先完成一组单词训练，阅读会更贴合你今天的词。

[开始单词训练]
```

#### 设计规则

- 首页首屏只放一个主按钮；
- 单词和阅读任务卡可以并列显示状态，但不能和主任务抢主按钮；
- 教练建议摘要最多 2 行；
- 完成状态优先显示“明天优先复习什么”，而不是庆祝动效；
- 用邻近性把“当前建议”和主按钮绑定，用连续性让闭环轨迹指向下一步。

#### 状态细化

| 状态 | 主卡内容 | 主行动 |
|---|---|---|
| 无记录 | 先学习 5 个考研核心词，生成第一篇阅读 | 开始第一组单词 |
| 单词未完成 | 完成近期词复习，准备生成阅读 | 开始单词训练 |
| 单词完成 / 阅读未做 | 用刚复习的词生成阅读 | 生成今日阅读 |
| 阅读完成 / 未看建议 | 推断题或薄弱词摘要 | 看教练建议 |
| 今日完成 | 今日闭环完成，明天优先复习薄弱词 | 查看今日总结 |
| AI 不可用 | 使用预置阅读继续完成今日任务 | 使用预置阅读 |

### 4.2 单词训练页

#### 页面目标

让用户快速完成知识输入，并留下真实掌握反馈。

#### 信息优先级

1. 当前词；
2. 查看释义或掌握反馈；
3. 例句和考研语境提示；
4. 本轮进度；
5. 退出或稍后继续。

#### 推荐结构

```text
单词训练
├── 顶部轻量进度：第 6 / 20 个
├── 单词卡片：英文词 + 提示
├── 展开区：释义 + 例句 + 考研语境
├── 三态反馈：认识 / 模糊 / 不认识
└── 底部提示：这些词会用于稍后的阅读
```

#### 设计规则

- 训练中隐藏复杂导航，只保留返回和进度；
- 单词卡片居中但不空洞，保证释义展开后仍能一屏理解；
- “认识 / 模糊 / 不认识”视觉权重一致，避免诱导用户选“认识”；
- 薄弱词反馈不使用责备语气，只提示后续会回炉。

#### 本轮结果页

```text
本轮完成
认识 14 · 模糊 4 · 不认识 2

建议先用这些词做一篇阅读，看看它们在文章里是否稳定。

[生成阅读]
[稍后再说]
```

结果页主行动是“生成阅读”；“稍后再说”为文本按钮。

### 4.3 阅读训练页

#### 页面目标

把近期单词放入考研阅读语境，并通过题目检测理解。

#### 信息优先级

1. 阅读来源与目标词；
2. 文章正文；
3. 题目；
4. 答案解析；
5. 错词回流和教练建议。

#### 四个模式

| 模式 | 页面重点 | 主行动 |
|---|---|---|
| 生成前 | 说明使用哪些近期词、预计题型和用时 | 生成今日阅读 |
| 阅读中 | 正文可读性、目标词轻标记、少干扰 | 开始答题 |
| 答题中 | 题目、选项、作答进度 | 提交答案 |
| 解析中 | 正确率、错因、原文依据、下一步 | 看教练建议 |

#### 阅读模式设计规则

- 阅读正文使用白色或近白卡片，行高 1.55–1.7；
- 目标词标记用浅底色或下划线，不打断阅读；
- 词汇提示默认折叠，用户点击目标词再查看；
- 答题入口固定在正文之后或底部，不悬浮遮挡正文；
- 解析必须给出原文依据，不只显示对错。

#### AI 失败降级

```text
暂时无法生成新文章
可以先使用预置考研阅读继续练习，本次建议会标注为“基于预置阅读”。

[使用预置阅读]
[重试生成]
```

降级规则：

- 不清空已选择的目标词；
- 不假装 AI 已成功生成；
- 预置阅读完成后仍进入解析和教练建议。

---

### 4.4 教练建议页

#### 页面目标

把学习记录转化为具体下一步，而不是展示复杂统计。

#### 信息优先级

1. 今日一句话建议；
2. 当前表现判断；
3. 主要原因；
4. 下一步任务；
5. 可折叠学习画像。

#### 推荐结构

```text
教练建议
├── 今日建议：一句话
├── 当前判断：词汇 / 阅读 / 题型
├── 原因解释：不超过 3 点
├── 下一步任务：复习词 + 阅读题型 + 复盘重点
├── 学习画像摘要：可展开
└── 主行动：开始推荐任务
```

#### 设计规则

- 教练建议页不使用仪表盘首屏；
- 所有数据后面必须连接行动；
- 数据不足时给入门建议，不生成伪个性化结论；
- 鼓励反馈放在底部，不能替代判断和行动。

#### 示例

```text
今日建议
先复习 4 个薄弱词，再做一篇包含推断题的阅读。

当前判断
词汇识别稳定，但在长句和转折语境里不够稳。

下一步
1. 复习 context、assume、maintain、evaluate
2. 做 1 篇推断题强化阅读
3. 复盘 however / although 后面的作者态度

[开始薄弱词复习]
```

## 5. 组件系统与原子设计

组件系统按原子设计组织，但只沉淀能复用且能保持学习体验一致的层级。不要为首版制造空泛抽象。当前 UI 基座采用 `shadcn_ui` + EnglishLover `EL*` 包装组件的复合方案：`shadcn_ui` 提供高质量基础组件，`EL*` 层负责业务语义、token 固化和页面一致性。

### 5.1 原子设计层级

| 层级 | 本项目元素 | 约束 |
|---|---|---|
| Tokens | 颜色、字号、间距、圆角、elevation、动效时长 | 先定义为 Flutter theme 或常量，页面不得散落硬编码 |
| Atoms | 主按钮、次按钮、文本按钮、状态标签、进度文本、目标词标记 | 必须有可访问标签、禁用态和加载态 |
| Molecules | 单词卡、任务卡、教练便签、反馈卡、题目选项组 | 同类结构保持相同间距、形状和语义色 |
| Organisms | 首页今日计划区、单词专注外壳、阅读专注外壳、解析结果区 | 只承载一个学习阶段，不混入跨阶段入口 |
| Templates | 今日学习模板、训练模板、阅读模板、教练建议模板 | 明确主行动位置和导航显隐规则 |
| Pages | 今日、单词、阅读、教练四个产品页 | 页面只组合模板，不重新定义基础视觉规则 |

### 5.2 EL 组件层与 shadcn_ui 分工

| 层级 | 组件 / 能力 | 职责 | 使用规则 |
|---|---|---|---|
| 基础组件 | `shadcn_ui` | 提供按钮、卡片、徽标、进度、导航等基础质量和交互状态 | 页面不直接依赖裸组件表达业务语义，优先走 `EL*` 包装 |
| 主题 token | `ELTokens` / `ELTheme` | 固化颜色、间距、圆角、阴影、文字层级和 Material 导航主题 | 新颜色、新圆角、新阴影必须先进入 token，再进入页面 |
| 行动组件 | `ELButton` | 统一主/次/描边/文本行动按钮 | 同屏只有一个 `primary`；加载、禁用和可访问标签必须保留位置 |
| 容器组件 | `ELCard` | 统一任务、阅读、反馈、结果容器 | 默认使用边框 + 轻阴影；不要在页面内重复写卡片样式 |
| 状态标签 | `ELBadge` | 统一状态、目标词、题型和风险标签 | `coach` 表当前/完成，`word` 表薄弱词/目标词，`danger` 表错误/降级 |
| 学习路径 | `ELLearningPath` | 展示“单词 -> 阅读 -> 解析 -> 建议”闭环 | 只用于结构提示，不作为装饰分割线 |
| 数据摘要 | `ELStatChip` | 展示少量轻量统计 | 数据必须连接下一步行动，不做独立看板 |
| 状态反馈 | `ELEmptyState` 及后续 Error / Loading 变体 | 空、加载、错误、成功、禁用均给出下一步 | 优先页面内反馈，弹窗只用于确认或阻断性选择 |

页面实现顺序固定为：先复用 `EL*`，再组合 `shadcn_ui` 基础组件；只有当现有组件无法表达新的业务语义时，才新增 `EL*` 组件。

### 5.3 主行动按钮

- 每个页面同一屏最多一个主行动；
- 使用 Oxford Blue；
- 文案必须是动词短语：开始单词训练、生成今日阅读、提交答案、看教练建议；
- 加载时保留按钮位置，文案改为进行中状态。

### 5.4 任务卡

任务卡用于首页和结果页，结构固定：

```text
[状态标签]
任务名称
一句说明
关键数据（最多 3 个）
[主行动或次行动]
```

禁止在任务卡内堆叠长列表、图表或两个以上同级按钮。首页已有主任务卡时，单词/阅读摘要卡中的按钮必须降级为次按钮、描边按钮或文本入口，不能与主任务抢同一视觉权重。

### 5.5 教练便签卡

用于短建议，结构固定：

```text
教练建议
一句判断。
下一步：一个明确动作。
```

便签卡不是聊天气泡，不提供自由聊天入口。

### 5.6 进度提示

- 学习中使用轻量进度条或文字：`第 6 / 20 个`；
- 首页使用闭环轨迹表达整体进度；
- 不使用连续打卡火焰、排行榜或强刺激进度系统。

### 5.7 状态反馈

| 状态 | UI 规则 | 文案规则 |
|---|---|---|
| Loading | 骨架屏或轻量进度，不遮盖已存在内容 | 说明正在做什么 |
| Empty | 简洁空卡 + 一个主行动 | 告诉用户第一步 |
| Error | 错误卡 + 重试 + 降级 | 说明影响和恢复路径 |
| Success | 结果摘要 + 下一步 | 不过度庆祝 |
| Disabled | 降低对比 + 条件说明 | 说明如何解锁 |

## 6. 专注模式与专注力约束

专注模式是单词背诵和阅读理解的学习中状态，不是新的一级页面。用户从首页、单词页或教练建议页点击开始训练后，界面进入专注模式；完成当前轮次、主动返回或确认退出后离开专注模式。

### 6.1 专注模式通用外壳

```text
专注模式
├── 顶部：返回 / 当前任务标题 / 轻量进度
├── 主内容：当前词或当前阅读材料
├── 当前任务反馈：掌握反馈、答题选项或解析
└── 底部：唯一主行动
```

通用规则：

- 隐藏底部导航、学习画像、历史统计、设置入口和非当前任务推荐；
- 顶部只保留返回、任务标题和轻量进度，不放入口型导航；
- 同屏最多一个主行动，次行动降为文本或折叠到结果页；
- 主内容使用 Level 2 Focus 表面，利用封闭性说明“此刻只处理这里”；
- 阶段切换使用共同命运：正文、题目、解析分别成组出现，不在同屏抢焦点；
- 退出未完成训练时才出现确认弹窗，避免误触丢失进度；
- 完成当前轮次后可退出专注模式，或切换到下一段专注任务。

### 6.2 单词背诵专注模式

触发：用户点击“开始单词训练”“开始第一组单词”“开始薄弱词复习”后进入。

```text
单词专注模式
├── 顶部：第 6 / 20 个 · 本轮单词
├── 当前词：significant
├── 释义揭示：查看释义 / 收起释义
├── 语境提示：例句 + 考研语境
└── 掌握反馈：认识 / 模糊 / 不认识
```

设计规则：

- 当前词和三态反馈是视觉中心；
- “认识 / 模糊 / 不认识”权重一致，避免诱导选择；
- 进度只显示当前位置和本轮总量，不展示复杂统计；
- 标记反馈后自动进入下一个词，不弹出额外确认；
- 完成本轮后展示结果摘要，并以“用这些词生成阅读”为主行动。

### 6.3 阅读理解专注模式

触发：用户点击“生成今日阅读”后进入生成前/生成中状态；文章生成成功、使用预置阅读、开始阅读正文或进入答题后保持阅读专注模式。

```text
阅读专注模式
├── 顶部：阅读进度 / 题目进度
├── 阅读正文：标题 + 正文 + 轻量目标词标记
├── 可选提示：目标词提示默认折叠
├── 答题区：题目、选项、当前题进度
└── 解析区：答案、原文依据、错因、下一步
```

设计规则：

- 阅读正文优先，生成说明、目标词和题目分阶段出现；
- 目标词提示默认折叠，点击目标词再查看释义或语境；
- 阅读中主行动是“开始答题”，答题中主行动是“提交答案”，解析中主行动是“看教练建议”；
- AI 失败时在当前专注模式内提供“使用预置阅读”和“重试生成”，不跳回首页；
- 解析必须给出原文依据和下一步，不只显示正确/错误。

### 6.4 专注模式中的隐藏项

在单词背诵、阅读正文、答题和解析中，默认隐藏或弱化：

- 底部导航；
- 学习画像入口；
- 设置入口；
- 历史记录入口；
- 复杂统计；
- 非当前任务的推荐；
- “再做一篇”等可能抢占当前闭环的行动。

### 6.5 弹窗使用限制

只允许以下场景使用弹窗：

- 用户退出未完成训练；
- AI 内容生成失败且需要选择重试或降级；
- 提交答案前确认未答题项。

其他提示使用页面内反馈，不打断学习。

### 6.6 次级行动排序

当页面需要多个行动时，权重固定：

```text
主按钮：继续当前闭环
次按钮：查看解释 / 稍后再说
文本按钮：返回 / 更换 / 跳过
```

不能让“再做一篇”“查看统计”“更换文章”与主闭环行动同权重。

## 7. 响应式与包容性设计

### 7.1 移动端优先

- 底部导航：今日 / 单词 / 阅读 / 教练；普通页面显示，专注模式隐藏；
- 单列卡片；
- 主行动靠近内容结尾，学习流程可使用底部固定按钮；
- 阅读正文宽度跟随屏幕，保持舒适行高。

### 7.2 桌面端延展

- 普通内容列居中，建议最大宽度 720–840px；宽屏 App Shell 可扩展到约 1040px 以容纳双栏；
- 阅读页可使用双栏：正文在左，目标词/题目进度在右；
- 首页可以把任务卡横向排列，但当前建议仍占主视觉；
- 不因屏幕变宽而增加额外入口。

### 7.3 包容性场景

| 场景 | 设计要求 |
|---|---|
| 低视力或强光环境 | 正文保持高对比；提醒色必须配文字，不单独表达语义 |
| 单手移动端学习 | 主行动靠近内容结束或底部安全区；触控目标不小于 44px |
| 注意力疲劳 | 专注模式隐藏导航、统计和推荐；每屏只处理一个学习任务 |
| 网络慢或 AI 失败 | 保留已选目标词，给出重试和预置阅读，不中断闭环 |
| 减少动态效果 | 状态切换可关闭或弱化，不使用闪烁、抖动、循环氛围动画 |

## 8. 可实现性约束

当前代码事实：Flutter 应用已使用 `EnglishLoverApp`、`ShadApp`、`ELTheme`、`ELTokens`、`ELAppShell` 和项目组件组织今日、单词、阅读、教练四个页面；依赖中已有 `shadcn_ui`，但没有图表库、项目自定义字体资产或复杂动画库。因此设计优化应优先复用现有 token 与组件，不新增视觉依赖。

### 8.1 复用现有实现的默认方案

| 需求 | 默认实现方向 |
|---|---|
| 卡片 | `ELCard` / `ShadWarm Card`，使用 `ELTokens` 控制圆角、边框和轻量阴影 |
| 底部导航 | 复用 `ELAppShell` 的 `NavigationBar` / `NavigationRail`；专注模式需要显式隐藏 |
| 主按钮 | `ELButton.primary`，保持每屏一个主行动 |
| 次按钮 | `ELButton.secondary` / `ELButton.outline` / `ELButton.ghost` |
| 进度 | `ShadProgress` + 文本进度，保留语义标签 |
| 标签 | `ELBadge`，按 coach / word / neutral / danger tone 映射语义 |
| 阅读正文 | `ELCard` + `Text` / `Text.rich`，复用阅读 text style 和目标词轻标记 |
| 状态反馈 | `ELEmptyState` 或页面内反馈卡，不默认弹窗 |

### 8.2 Token 落地建议

后续新增页面或组件时应先扩展现有主题常量，再写页面：

```text
颜色 -> 字号 -> 间距 -> 圆角 -> 组件变体 -> 页面
```

禁止在多个页面各自硬编码颜色和按钮样式；新组件必须先判断能否由现有 `EL*` atom/molecule 扩展。

## 9. UI 验收清单

### 9.1 首页

- [ ] 用户 10 秒内能看出今天先做什么；
- [ ] 首屏只有一个主按钮；
- [ ] 单词、阅读、教练建议的关系可见；
- [ ] 今日完成状态给出明日或下一步建议。

### 9.2 单词训练

- [ ] 进入单词训练后隐藏底部导航并显示专注模式外壳；
- [ ] 当前词和反馈按钮是视觉中心；
- [ ] 进度清楚但不抢焦点；
- [ ] 三个掌握反馈按钮权重一致；
- [ ] 结果页明确引导生成阅读。

### 9.3 阅读训练

- [ ] 进入阅读正文和答题后隐藏底部导航并显示专注模式外壳；
- [ ] 阅读正文行高、段距、对比度适合长时间阅读；
- [ ] 目标词标记不破坏阅读；
- [ ] 答题和解析状态清楚分离；
- [ ] AI 失败时可使用预置阅读继续闭环。

### 9.4 教练建议

- [ ] 建议由“判断 / 原因 / 下一步”组成；
- [ ] 数据不足时不伪装个性化；
- [ ] 学习画像是摘要或折叠内容；
- [ ] 主行动指向下一次学习任务。

### 9.5 全局

- [ ] 所有错误、空状态、成功状态都有下一步；
- [ ] 没有排行榜、商城、社区等非首版入口；
- [ ] 没有超过一个同屏主 CTA；
- [ ] 单词背诵和阅读理解开始后均进入专注模式；
- [ ] 颜色、间距、圆角、字体层级可沉淀为主题 token；
- [ ] 页面分组符合格式塔邻近性、相似性和连续性；
- [ ] 视觉风格符合“极简考研学习界面”，未使用绿色主色、大面积深色实心块、大面积新拟物或炫技动效；
- [ ] 组件能归入 token / atom / molecule / organism / template / page 层级。
